## 1. 设计目标与原则

### 1.1 UI 层设计目标

| 目标 | 含义 |
|---|---|
| **内容优先** | 简历、JD、文案是主角，UI 不抢戏；装饰性元素最小化 |
| **可信专业** | 求职材料场景，视觉传达可信赖感（深蓝主色、克制配色） |
| **高效工作台** | 信息密度中等偏高（density 7），操作路径短，重复任务（投递循环）成本低 |
| **AI 透明可控** | Human-in-the-loop：AI 生成内容始终可审、可改、可弃；生成过程可见（流式） |

### 1.2 PRD 原则 → UI 落实

| PRD 原则 | UI 落实 |
|---|---|
| Evidence First | 项目详情页独立 Evidence 区；证据类型徽标（GitHub/代码/Demo…） |
| 一份经历，多种表达 | 表达版本 Tab + 版本历史留档 UI（v1/v2，可比较回退） |
| LLM 负责认知，程序负责确定性 | 统计卡（Dashboard）由后端计算直出；无"AI 估算"类标识 |
| Human-in-the-loop | 「确认 / 编辑 / 重新生成」三动作模式（§4.1），AI 草稿状态显式标注 |
| 分阶段呈现 | 内容迭代 MD 预览 ⇄ 定稿 HTML 预览切换（§5.6） |
| 素材先行 → 定制循环 | 侧边栏按两段式分组，强化产品心智（§3.2） |

## 2. 设计系统

### 2.1 设计语言

- **Flat Design（专业简约变体）**：2D、无渐变、极浅阴影、边框分层、Typography-focused
- 来源：ui-ux-pro-max 检索匹配（Flat Design + Poppins/Open Sans + 蓝绿配色），按产品性质做落地适配（见各节「适配说明」）
- 卡片无阴影（border 分层）；浮层（Modal / Drawer / Dropdown）用浅阴影区分层级

### 2.2 色彩系统

### 2.3 状态与语义色（枚举 → 标签规范）

匹配三态（skill_match_status）：

| 状态 | 图标 | 颜色 |
|---|---|---|
| 强匹配 strong | ✓ Check | `#16A34A` |
| 部分匹配 partial | △ TriangleAlert | `#D97706` |
| 缺失 missing | ✗ X | `#DC2626` |

投递七态（application_status）：

| 状态 | 图标 | 颜色 |
|---|---|---|
| 待投递 to_apply | CircleDashed | slate |
| 已投递 applied | Send | blue |
| 已回复 replied | MessageCircle | cyan |
| 面试 interview | Users | violet |
| Offer offer | BadgeCheck | green |
| 拒绝 rejected | XCircle | red |
| 无回复 no_response | MessageCircleOff | gray |

其他状态：`expression_status` draft（灰 / FileText）/ confirmed（绿 / CheckCircle2）；`reflection_status` pending（琥珀 / Clock）/ passed（绿 / ShieldCheck）/ issues（红 / ShieldAlert）；`analysis_status` processing（蓝 / Loader 旋转）/ completed / failed（红）。

> 规范：**状态一律 icon + 色 + 文字三重编码**（可访问性要求，见 §7），不允许纯色块或纯颜色文字。

### 2.4 字体系统

- **标题 / 大数字**：Poppins（600/700），中文回退 PingFang SC → Microsoft YaHei → Noto Sans SC
- **正文**：Open Sans（400/500/600），中文回退同上
- **等宽**（代码、GitHub 链接、数字）：ui-monospace / SFMono-Regular / Consolas

```css
font-family: "Open Sans", "PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif;
font-family: "Poppins", "PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif; /* headings */
```

字号阶梯（density 7 工作台）：

| 级别 | 字号/行高 | 用途 |
|---|---|---|
| xs | 12/16 | 辅助标签、表格注释（不用于正文） |
| sm | 14/20 | **正文默认**、表格单元格、表单项 |
| base | 16/24 | 强调段落、大输入区 |
| lg | 18/28 | 卡片标题、分组标题 |
| xl | 20/28 | 页面标题 |
| 2xl | 24/32 | Dashboard 统计数字 |

### 2.5 间距与栅格

- 4px 基栅格：4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48
- 页面内边距 24–32px；卡片内边距 16–24px；表单组间距 24px；栅格 gap 16px
- 触控目标 ≥ 40px（桌面工作台按 40px 按钮高，见 §7）

### 2.6 圆角 / 阴影 / 边框

- 圆角：按钮与输入 6px、卡片 8px、Modal 12px、状态标签 pill（999px）
- 阴影：卡片无阴影；浮层 `0 4px 12px rgba(15,23,42,.08)`；禁止大投影与渐变

### 2.7 图标

- 统一 **Lucide**（lucide-react），24px 网格、stroke 1.75
- 常用尺寸 16 / 18 / 20；**禁止 emoji 作图标**
- 纯装饰图标 `aria-hidden="true"`；可交互图标必须有可访问名称（aria-label / 相邻文字）

### 2.8 动效规范（motion 3 微妙）

| 场景 | 时长 | 说明 |
|---|---|---|
| hover / active / focus 反馈 | 150ms | 颜色 / 透明度位移，`ease-out` |
| 折叠 / 展开 | 200ms | 高度动画使用 grid-template-rows 技巧，禁直接动画 height |
| Modal / Drawer 进出 | 250ms | 淡入 + 12px 位移 |
| **AI 流式输出** | 逐字渲染 | 打字机式，末尾光标脉冲；**禁止 10s+ spinner 干等** |
| 列表加载 | 骨架屏 | 骨架 + `aria-busy`，禁用闪烁 spinner |
| 页面切换 | 无动画 | 工作台不做页面转场 |

- 全部动效尊重 `prefers-reduced-motion: reduce`（直接渲染最终态）
- 动效必须传达意义（流式 = 生成进行中、骨架 = 布局占位），不做纯装饰动画

## 4. 通用交互模式（跨页面）

### 4.1 AI 生成模式（本产品核心交互）

```text
┌─ 触发 ──→ ── 生成中 ──→ ── 待确认（AI 草稿）──┐
│             流式输出       确认 / 编辑 / 重新生成 │
│             + 停止按钮                           ↓
└─────────────────────────────── 失败：错误提示 + 重试
```

- **流式输出**：AI 文本逐字渲染（`aria-busy`），生成中主按钮变「停止」；完成后 `aria-live` 播报"生成完成"（流式过程不逐字播报，防读屏刷屏）
- **三动作确认条**（Human-in-the-loop 落点）：
  - 「确认」→ 内容落库（expression_status / 快照 → confirmed / 保存版本）
  - 「编辑」→ 进入内联编辑态，编辑后手动保存
  - 「重新生成」→ 二次确认（覆盖当前草稿？）→ 重新调用 Agent；已确认内容重新生成时**保留历史留档**（数据模型决策 #5）
- **AI 草稿标注**：未确认内容卡片显示「AI 草稿」角标（amber），确认后变「已确认」（green）
- **反馈**：生成结果卡提供 👍/👎（agent_runs 记录，为后续调优留数据）；「重新生成」即隐含负反馈，MVP 不做更复杂反馈流

### 4.2 加载反馈分级

| 等待时长 | 反馈 |
|---|---|
| < 200ms | 无反馈（避免闪烁） |
| 200ms–1s | 按钮内 loading（局部） |
| > 1s（列表/查询） | 骨架屏 + `aria-busy` |
| AI 长任务 | 流式输出（§4.1），禁止长 spinner |
| 导出 PDF / 生成 HTML | 按钮 loading + 完成 Toast；PDF 下载 |

### 4.3 状态标签系统

- 所有枚举统一渲染为 pill 标签：`icon + 文字 + 语义色浅底 + 深色文字`（§2.3 色表）
- 可交互标签（如状态下拉）hover 加深；纯展示标签不可点

### 4.4 表单规范

- **可见 label**（禁 placeholder-only）；必填标 `*`；错误就地显示（红色文字 + icon + 边框），不用顶部汇总替代
- 提交反馈链：`点击 → loading → 成功 Toast / 失败就地错误`，禁止静默失败
- 长表单分组（分组标题 + 说明文字）；字段级 helper text（STAR 提示落位，见 §5.2.2）
- 校验：前端即时校验 + 后端返回就地映射

### 4.5 空状态

每个列表页定义空状态：图标 + 一句话说明 + 主 CTA（如 Projects 空 →「添加第一个项目」；JD 空 →「粘贴 JD 开始分析」）。空状态是引导，不是死胡同。

### 4.6 确认与危险操作

- 删除：ConfirmDialog（红按钮 + 说明后果，如删除项目将级联删除证据与表达）
- 重新生成已确认内容：提示「将生成新版本，旧版本保留可回退」
- 未保存离开：拦截提示（编辑器 / 表单脏状态）

## 6. 响应式策略

- **桌面优先**（简历编辑、双栏 Studio、宽表格为桌面场景）；完整体验 ≥ 1280px
- **1024–1279px**：Studio 左栏收窄至 40%；Dashboard 统计卡 2×2
- **768–1023px**：侧边栏折叠为 64px 图标态；JD 结果页双栏变单栏堆叠；Reflection 面板移到底部
- **< 768px（MVP 最低限度）**：应用壳保持可用（抽屉导航），Studio 编辑/预览改 Tab 切换（不并排）；表格变卡片列表。移动端不作为 MVP 目标，但不可横向滚动、不可禁用缩放

## 7. 可访问性（关键约束）

1. 正文对比度 ≥ 4.5:1（色彩系统已按此校验）；状态不只用颜色（icon + 文字 + 颜色三重编码）
2. 表单：可见 label、错误就地、键盘可达；占位符不替代 label
3. 焦点：所有交互元素可见 focus ring（`--color-ring` 2px + 偏移）；Tab 顺序自然
4. 触控目标 ≥ 40px；图标按钮 aria-label
5. AI 流式：`aria-busy` 生成中，完成 `aria-live="polite"` 一次性播报；流式过程不逐字播报
6. `prefers-reduced-motion` 下流式输出改**分段展示**（段落到达即显示，不做打字动画）
7. Modal / Drawer：焦点圈定、Esc 关闭、背景不可滚动；打开时焦点入内，关闭归还触发元素
