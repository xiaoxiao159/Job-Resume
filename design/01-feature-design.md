## 2. 主流程（已确认）

```text
【资产准备阶段（一次投入，持续积累）】
1. Career Assets 盘点（结构化问卷 + AI 对话深挖）→ AI 辅助填写产出通用版表达
2. Project Agent 求职场景表达（简历版 Bullet / 面试版 / STAR 版，不依赖 JD）
        ↓
【求职定制阶段（每次投递）】
3. 粘贴 JD → JD Agent 分析
        ↓
4. JD Match 匹配决策（相关项目 / 技能命中 / 缺口）
        ↓
5. Resume Agent 定制整份简历（JD 驱动：选取 / 排序 / JD 化措辞）
        ↓
6. Reflection 验证（匹配度 + 编造检查）→ MD 预览 → 用户迭代调整
        ↓
7. Resume Studio 选模板 → 生成 HTML / PDF
        ↓
8. HR Agent 开场白
        ↓
9. Application Log 投递记录
```

### 关键设计点

1. **两层表达**：AI 辅助填写（盘点时）产出通用版；Project Agent（专用 LLM + Prompts）产出求职场景表达；Resume Agent 做 JD 化定制
2. **素材先行**：先盘点、再表达、后组装——Project Agent 前置且不依赖 JD（PRD §2.1 问题二的解法）
3. **匹配决策**：JD Match 结果作为简历定制（选取 / 排序 / 措辞）的依据
4. **技能调整限定在简历展示层**：资产库不被 JD 改写
5. **Reflection 迭代环**：匹配度验证 + 编造检查（程序校验 + LLM 自检），发现问题回到定制步骤调整，直到用户满意
6. **分阶段呈现**：迭代阶段用 Markdown 版预览（内容优先），选定模板后用 HTML 版（视觉优先）
7. **多版本按需生成**：简历版 Bullet 在资产准备阶段生成；面试版 / STAR 版按需触发
8. **Prompt 统一管理**：所有 Prompt 放 backend/prompts/，Jinja2 模板文件管理，不进代码

## 3. 模块明细

### M1 Career Assets 求职资产

定位：系统核心数据基础，是 Agent 可持续调用的求职资产库。**先盘点清楚，后面才好包装。**

#### F1.1 Basic Info 基本信息与求职意向

- 基本信息（必填）：姓名、邮箱、电话、GitHub
- 基本信息（可选）：个人主页
- 求职意向：意向岗位、城市、到岗时间（枚举：立即到岗 / 一周内 / 两周内 / 一个月内 / 待定）
- 用途：简历头部展示；定制简历与 HR 开场白时调用；求职意向可参与 JD Match 提示（如城市不符）

#### F1.2 Projects 项目（重点）

字段：项目名称、项目简介、项目背景、项目目标、项目时间、项目角色、技术栈、个人职责、核心工作、技术难点、解决方案、项目成果、GitHub/Demo、Evidence。

- **F1.2.1 项目 CRUD**：增删改查。
- **F1.2.2 填写引导**：表单内字段级提示文案与示例；提供 STAR 法（Situation / Task / Action / Result）参考模板，帮助用户知道"该写什么"。
- **F1.2.3 AI 辅助填写（盘点模式，两段式）**：第一段为结构化问卷，快速收集基础信息（背景 / 目标 / 技术栈等）；第二段为多轮对话，AI 深挖细节（为什么做、解决什么问题、核心难点、个人具体贡献、成果量化）。AI 将结果提炼回填到项目字段，**用户确认后保存**。产出：事实完整 + 专业表达的项目资产（**通用版表达**，供后续 Agent 使用）。
- **F1.2.4 AI 优化**：对已填写的项目内容进行润色改写。基于事实，禁止编造。

#### F1.3 Evidence 证据

类型：GitHub、代码、项目文档、实验结果、项目截图、Demo、论文、其他。挂在 Project 上，支撑 Evidence First 原则。

#### F1.4 Skills 技能

技能名称、熟练程度、关联项目。供 JD Match 做技能匹配。

#### F1.5 Education 教育背景

必填，支持多条（如本科 + 硕士）。每条：{学校、专业、阶段（本科 / 硕士 / 博士）、时间}，可选补充主修课程。

#### F1.6 Research / Campus 科研与校园经历

均为可选。结构为项目经历的精简版（名称、角色、时间、描述）。

#### F1.7 Honors 荣誉证书

可选。证书 / 荣誉名称、时间。

#### F1.8 自我评价

可选。个人自评文本，定制简历时可调用、可重写。

### M2 JD Analysis JD 分析

- **F2.1 JD 输入**：粘贴 JD 文本（明确不做 URL 解析、爬虫）。
- **F2.2 JD Agent 分析**：输出岗位画像——岗位名称、核心技能（含星级）、加分项、岗位职责、经验要求、学历要求、关键词。
- **F2.3 JD Match 岗位匹配**：JD 要求 vs Career Assets，输出总体匹配度 + 三类清单（强匹配 ✓ / 部分匹配 △ / 缺失 ✗）。
- **F2.4 Gap Analysis**：你的优势 / 你的不足。
- **F2.5 JD 历史记录**：分析结果随 JD 保存，提供历史列表页可回看。

### M3 Project Agent 项目表达（素材层）

定位：把盘点好的项目资产转化为**求职场景表达**（PRD §2.1 问题二的解法）。前置、不依赖 JD；针对具体 JD 的措辞调整由 M4 Resume Agent 完成。

- **F3.1 输入**：资产库中已盘点的项目（含 AI 辅助填写产出的通用版）。
- **F3.2 三种输出表达**：
  - 简历版：1~3 条高质量 Bullet；
  - 面试版：项目背景 / 我的职责 / 技术架构 / 核心难点 / 解决方案 / 最终效果；
  - STAR 版：Situation / Task / Action / Result。
- **F3.3 按需生成**：简历版 Bullet 在资产准备阶段生成，供 Resume Agent 组装取用；面试版 / STAR 版进入面试阶段后按需触发。

### M4 Resume Agent 简历定制（组装层）

- **F4.1 Targeted Resume 生成**：根据 JD + Career Assets（含 Project Agent 表达）+ Evidence，定制**整份简历**（教育 / 项目 / 技能 / 自我评价等全部内容段）：选取、排序、JD 化措辞。
- **F4.2 简历版本管理（按岗位分类保存）**：每份简历带有目标岗位分类字段；简历列表按岗位分类分组 / 筛选（如 Master、AI 应用工程师、Agent 工程师、后端开发），后续针对同类岗位投递可直接复用该版本。
- **F4.3 三类优化**：
  - 内容重写：原始经历 → 专业表达；
  - JD 定制：相关项目优先、相关技能突出、不相关内容弱化；
  - Bullet 优化：单句事实 → 结构化 Bullet。
- **F4.4 安全边界**：禁止编造项目 / 工作经历 / 技术栈 / 数字 / 项目成果；允许改写、重组、提炼、调整顺序、突出关键词、根据 JD 调整表达。
- **F4.5 Reflection 验证（迭代环）**：
  - 匹配度验证：简历内容 vs JD 要求清单（关键词 / 要求覆盖）；
  - 编造检查：简历内容 vs 资产库事实（技术栈、数字、项目是否存在于资产库），程序校验 + LLM 自检；
  - 发现问题回到 F4.1 / F4.3 调整，迭代直到用户满意。

### M5 Resume Studio 简历工作台

- **F5.1 简历列表**：按目标岗位分类展示。
- **F5.2 编辑器与分阶段预览**：左右布局——左侧内容编辑，右侧实时预览；内容迭代阶段用 Markdown 版预览（内容优先），选定模板后用 HTML 版预览（视觉优先）。
- **F5.3 模板**：Classic / Modern / Minimal 三套；内容与视觉模板分离（Resume JSON → 模板引擎 → HTML → CSS）；可选模块（科研 / 校园 / 荣誉 / 自我评价）为空时自动隐藏该段落。
- **F5.4 导出**：HTML、PDF（DOCX / LaTeX 留待未来）。

**F5.5 简历内容结构（8 段）**：

```text
1. 基本信息（姓名 / 邮箱 / 电话 / GitHub 必填；个人主页可选）
2. 教育背景（必填，可多条）
3. 科研经历（可选）
4. 校园经历（可选）
5. 项目经历（必填，来自 Projects 资产）
6. 荣誉证书（可选）
7. 专业技能（必填，来自 Skills 资产）
8. 自我评价（可选）
```

### M6 HR Agent 沟通文案

- **F6.1 场景**：Boss直聘 / 微信 / 邮件 / LinkedIn。
- **F6.2 模式**：简短版 / 标准版 / 技术版。
- **F6.3 结构**：我是谁 + 我有什么相关经历 + 为什么匹配这个岗位 + 希望进一步沟通。避免高度模板化。

### M7 Application Log 投递记录

- **F7.1 记录 CRUD**：公司、岗位、状态、投递时间、使用的简历版本、备注。
- **F7.2 状态流转**：待投递 / 已投递 / 已回复 / 面试 / Offer / 拒绝 / 无回复（极简表格，不做 Kanban 拖拽）。
- **F7.3 关联简历版本**：记录 resume_version_id，为后续 Resume A/B Testing 留数据基础。

### M8 Interview QA 面试问题记录

- **F8.1 QA CRUD**：公司、岗位、面试时间、问题、我的回答、复盘备注。
- **F8.2 按公司分组展示**。
- **F8.3 关联投递记录（可选）**：公司可从投递记录选取，自动带出岗位。为后续面试复盘与 Interview Agent 提供数据基础。

### M9 Dashboard 首页

- **F9.1 统计卡片**：投递数 / 回复数 / 面试数 / Offer 数。**由后端确定性计算**（如 回复率 = 回复数 / 投递数），不用 LLM 估算。
- **F9.2 最近投递列表**。
